> [!path] 🎯 Interview Prep
> **Who it's for:** Anyone preparing for a system design or ML system design interview.
> **Time:** ≈ 8–10 hours · **Lessons:** 21
> **Goal:** The topics interviewers ask about most, in the order you would use them in an interview.

## How to take this path

- Go top to bottom. Each lesson is one note; read the 🌱 basics note, then its 🔬 deep dive.
- **Tick the box** when you finish a lesson. Obsidian saves it, so you can stop and come back.
- Each note ends with **Check yourself** questions. Try them before peeking at the answers.
- Stuck on a word? Hover it, or look it up in the [[Glossary]].

## Lessons

### 📖 Foundations
- [ ] **1.** [[Requirements]] — Pinning down what the system must do and how well, before building. Then [[Requirements (Deep Dive)|🔬 deep dive]].
- [ ] **2.** [[Estimation]] — Quick math that tells you how big the problem really is. Then [[Estimation (Deep Dive)|🔬 deep dive]].
- [ ] **3.** [[Trade-offs]] — Every design choice gives something up; good design picks knowingly. Then [[Trade-offs (Deep Dive)|🔬 deep dive]].

### 📈 Scalability
- [ ] **4.** [[API Design]] — Designing the contract other programs use to talk to yours. Then [[API Design (Deep Dive)|🔬 deep dive]].

### 🏛️ Architecture
- [ ] **5.** [[SQL Databases]] — Tables with strict structure, joined and queried with SQL. Then [[SQL Databases (Deep Dive)|🔬 deep dive]].
- [ ] **6.** [[NoSQL Databases]] — Flexible databases built for scale and specific access patterns. Then [[NoSQL Databases (Deep Dive)|🔬 deep dive]].
- [ ] **7.** [[CAP Theorem]] — When the network breaks, a system must choose: stay correct or stay up. Then [[CAP Theorem (Deep Dive)|🔬 deep dive]].
- [ ] **8.** [[Replication]] — Keeping copies of data on several machines so one can fail. Then [[Replication (Deep Dive)|🔬 deep dive]].
- [ ] **9.** [[Sharding]] — Splitting data across machines so no one machine holds it all. Then [[Sharding (Deep Dive)|🔬 deep dive]].

### 📈 Scalability
- [ ] **10.** [[Caching]] — Keeping a copy of frequently used data somewhere faster. Then [[Caching (Deep Dive)|🔬 deep dive]].
- [ ] **11.** [[Load Balancing]] — Spreading incoming work across many servers so none is overwhelmed. Then [[Load Balancing (Deep Dive)|🔬 deep dive]].
- [ ] **12.** [[Message Queues]] — Buffers that let parts of a system hand off work without waiting. Then [[Message Queues (Deep Dive)|🔬 deep dive]].
- [ ] **13.** [[Rate Limiting]] — Capping how often someone can call you, to stay fair and safe. Then [[Rate Limiting (Deep Dive)|🔬 deep dive]].

### 🚀 Production
- [ ] **14.** [[High-Level Design]] — The big-picture blueprint: boxes, arrows and why. Then [[High-Level Design (Deep Dive)|🔬 deep dive]].
- [ ] **15.** [[Low-Level Design]] — Zooming into one part: its classes, data and interfaces. Then [[Low-Level Design (Deep Dive)|🔬 deep dive]].
- [ ] **16.** [[Case Studies]] — Classic systems designed step by step, applying everything above. Then [[Case Studies (Deep Dive)|🔬 deep dive]].

### 🎯 AI Foundations
- [ ] **17.** [[AI Architecture Layers]] — The four layers every AI system has: data, model, serving, monitoring. Then [[AI Architecture Layers (Deep Dive)|🔬 deep dive]].

### ☂️ The 12 Ribs
- [ ] **18.** [[Deployment & Serving]] — Putting a trained model where users and apps can call it. Then [[Deployment & Serving (Deep Dive)|🔬 deep dive]].

### 🤖 Modern LLM Systems
- [ ] **19.** [[Retrieval-Augmented Generation]] — Letting a model look things up before it answers. Then [[Retrieval-Augmented Generation (Deep Dive)|🔬 deep dive]].
- [ ] **20.** [[LLM Inference & Optimization]] — Making large models answer fast and cheaply. Then [[LLM Inference & Optimization (Deep Dive)|🔬 deep dive]].

### 🎓 Capstone

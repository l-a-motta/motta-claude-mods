> [!path] 🏗️ System Design Engineer
> **Who it's for:** Developers who want to design systems, not just build features.
> **Time:** ≈ 15–20 hours · **Lessons:** 38
> **Goal:** Cover all of Part 1 in order: read each basics note, then its deep dive.

## How to take this path

- Go top to bottom. Each lesson is one note; read the 🌱 basics note, then its 🔬 deep dive.
- **Tick the box** when you finish a lesson. Obsidian saves it, so you can stop and come back.
- Each note ends with **Check yourself** questions. Try them before peeking at the answers.
- Stuck on a word? Hover it, or look it up in the [[Glossary]].

## Lessons

### 📖 Foundations
- [ ] **1.** [[Object-Oriented Programming]] — Organizing code as objects that bundle data with the actions on it. Then [[Object-Oriented Programming (Deep Dive)|🔬 deep dive]].
- [ ] **2.** [[Design Patterns]] — Named, reusable solutions to problems that keep coming up in code. Then [[Design Patterns (Deep Dive)|🔬 deep dive]].
- [ ] **3.** [[Concurrency]] — Doing many things at once without the pieces tripping over each other. Then [[Concurrency (Deep Dive)|🔬 deep dive]].
- [ ] **4.** [[Data Structures]] — Ways of arranging data so the right questions are fast to answer. Then [[Data Structures (Deep Dive)|🔬 deep dive]].
- [ ] **5.** [[Operating Systems]] — The layer that shares one computer between many programs. Then [[Operating Systems (Deep Dive)|🔬 deep dive]].
- [ ] **6.** [[Networking]] — How computers find each other and exchange messages. Then [[Networking (Deep Dive)|🔬 deep dive]].
- [ ] **7.** [[Databases]] — Systems that store data safely and let you query it later. Then [[Databases (Deep Dive)|🔬 deep dive]].
- [ ] **8.** [[Requirements]] — Pinning down what the system must do and how well, before building. Then [[Requirements (Deep Dive)|🔬 deep dive]].
- [ ] **9.** [[Estimation]] — Quick math that tells you how big the problem really is. Then [[Estimation (Deep Dive)|🔬 deep dive]].
- [ ] **10.** [[Trade-offs]] — Every design choice gives something up; good design picks knowingly. Then [[Trade-offs (Deep Dive)|🔬 deep dive]].

### 🏛️ Architecture
- [ ] **11.** [[Monoliths]] — One program that does everything, deployed as a single unit. Then [[Monoliths (Deep Dive)|🔬 deep dive]].
- [ ] **12.** [[Microservices]] — Many small services, each owning one job, talking over the network. Then [[Microservices (Deep Dive)|🔬 deep dive]].
- [ ] **13.** [[Serverless]] — Running code without managing servers; you pay per use. Then [[Serverless (Deep Dive)|🔬 deep dive]].
- [ ] **14.** [[SQL Databases]] — Tables with strict structure, joined and queried with SQL. Then [[SQL Databases (Deep Dive)|🔬 deep dive]].
- [ ] **15.** [[NoSQL Databases]] — Flexible databases built for scale and specific access patterns. Then [[NoSQL Databases (Deep Dive)|🔬 deep dive]].
- [ ] **16.** [[Object Storage]] — Cheap, near-infinite storage for files like images, videos and backups. Then [[Object Storage (Deep Dive)|🔬 deep dive]].
- [ ] **17.** [[CAP Theorem]] — When the network breaks, a system must choose: stay correct or stay up. Then [[CAP Theorem (Deep Dive)|🔬 deep dive]].
- [ ] **18.** [[Replication]] — Keeping copies of data on several machines so one can fail. Then [[Replication (Deep Dive)|🔬 deep dive]].
- [ ] **19.** [[Sharding]] — Splitting data across machines so no one machine holds it all. Then [[Sharding (Deep Dive)|🔬 deep dive]].

### 📈 Scalability
- [ ] **20.** [[API Design]] — Designing the contract other programs use to talk to yours. Then [[API Design (Deep Dive)|🔬 deep dive]].
- [ ] **21.** [[REST]] — The web's most common API style: resources over plain HTTP. Then [[REST (Deep Dive)|🔬 deep dive]].
- [ ] **22.** [[gRPC]] — Fast, typed calls between services using compact binary messages. Then [[gRPC (Deep Dive)|🔬 deep dive]].
- [ ] **23.** [[WebSockets]] — A connection that stays open so the server can push updates instantly. Then [[WebSockets (Deep Dive)|🔬 deep dive]].
- [ ] **24.** [[Caching]] — Keeping a copy of frequently used data somewhere faster. Then [[Caching (Deep Dive)|🔬 deep dive]].
- [ ] **25.** [[CDN]] — Servers around the world that hand out content close to each user. Then [[CDN (Deep Dive)|🔬 deep dive]].
- [ ] **26.** [[Load Balancing]] — Spreading incoming work across many servers so none is overwhelmed. Then [[Load Balancing (Deep Dive)|🔬 deep dive]].
- [ ] **27.** [[Message Queues]] — Buffers that let parts of a system hand off work without waiting. Then [[Message Queues (Deep Dive)|🔬 deep dive]].
- [ ] **28.** [[Fault Tolerance]] — Designing so that when something breaks, the system keeps going. Then [[Fault Tolerance (Deep Dive)|🔬 deep dive]].
- [ ] **29.** [[Rate Limiting]] — Capping how often someone can call you, to stay fair and safe. Then [[Rate Limiting (Deep Dive)|🔬 deep dive]].

### 🚀 Production
- [ ] **30.** [[Authentication]] — Proving who someone is. Then [[Authentication (Deep Dive)|🔬 deep dive]].
- [ ] **31.** [[Authorization]] — Deciding what someone is allowed to do. Then [[Authorization (Deep Dive)|🔬 deep dive]].
- [ ] **32.** [[Encryption]] — Scrambling data so only the right people can read it. Then [[Encryption (Deep Dive)|🔬 deep dive]].
- [ ] **33.** [[Logging]] — Writing down what happened, event by event. Then [[Logging (Deep Dive)|🔬 deep dive]].
- [ ] **34.** [[Metrics]] — Numbers over time that show a system's health at a glance. Then [[Metrics (Deep Dive)|🔬 deep dive]].
- [ ] **35.** [[Distributed Tracing]] — Following one request as it hops across many services. Then [[Distributed Tracing (Deep Dive)|🔬 deep dive]].
- [ ] **36.** [[High-Level Design]] — The big-picture blueprint: boxes, arrows and why. Then [[High-Level Design (Deep Dive)|🔬 deep dive]].
- [ ] **37.** [[Low-Level Design]] — Zooming into one part: its classes, data and interfaces. Then [[Low-Level Design (Deep Dive)|🔬 deep dive]].
- [ ] **38.** [[Case Studies]] — Classic systems designed step by step, applying everything above. Then [[Case Studies (Deep Dive)|🔬 deep dive]].

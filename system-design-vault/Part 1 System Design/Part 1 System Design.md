> [!hub] 🏗️ Part 1 · System Design
> The handle of the umbrella: how any large software system is designed, AI or not.

Everything here applies to **any** large software system: a shop, a bank, a streaming service. Part 2 builds directly on it: the umbrella's handle is made of these ideas.

**See it as a picture:** [[System Design Map.canvas|🗺️ System Design Map]]

## What's inside

### 📖 [[Foundations]]
The building blocks every system stands on: code, computers, networks and how to think about a design.

- 💻 [[Programming]] — How software is organized and how it does many things at once.
- 🧠 [[Core Concepts]] — What every engineer knows about how computers store, run and move information.
- 💡 [[Design Basics]] — The habits of mind of a system designer: ask, estimate, choose.

### 🏛️ [[Architecture]]
How a system is cut into parts, where its data lives, and how many machines share the work.

- 🧱 [[Architecture Styles]] — The big shapes a system can take, from one program to many tiny functions.
- 🗄️ [[Data & Storage]] — The main families of storage and what each is good at.
- 🕸️ [[Distributed Systems]] — What changes when one computer is not enough and many must act as one.

### 📈 [[Scalability]]
How systems talk, stay fast, and keep working as traffic grows.

- 💬 [[Communication]] — How the parts of a system, and its users, talk to each other.
- ⚡ [[Performance]] — Making systems fast by doing less work and doing it closer to the user.
- 🛡️ [[Reliability]] — Keeping the system working when parts of it fail or traffic spikes.

### 🚀 [[Production]]
Running a system for real: keeping it secure, seeing inside it, and designing it on paper.

- 🔒 [[Security]] — Who are you, what may you do, and is the data safe on the way.
- 🔭 [[Observability]] — Seeing what a running system is doing, and why.
- 📁 [[Projects]] — Putting it all together: from a whiteboard sketch to real designs.

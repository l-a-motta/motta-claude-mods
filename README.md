# motta-claude-mods

Marketplace for personal mods for Claude Code: the one place a new machine restores them from. Every mod's code is in this repository, the third-party ones included, so any of them can be changed here.

## Mods

| `motta-statusline` | this repo | Two-line status line. Line 1: where the session runs (`📁 ui-tweaks  worktree`: its root, which only `/cd` or a worktree move changes; with `↳ plugins/x` right after it when a shell `cd` has taken the shell away from it), repo and branch links (the branch opens a GitHub compare view against origin's default), `files changed` or `files clean` in the branch's color, `↑`/`↓` against its upstream (`↑0 ↓0` when in step) or `not pushed`, the last commit's age, and the branch's PR (CI checks, conflicts or behind its base, review). Line 2: model and effort, then three bars of ten blocks of ten points: context (green under 30%, yellow to 50%, orange to 70%, red past it, with a white tick where auto-compact fires) and the 5h and 7d rate limits, each with a tick where the window's time stands (fill past it means the limit is going faster than the window; orange once 10 points ahead, yellow from 60%, red from 80%) and the time to reset (`2h45m`, `1d20h`). The desktop draws the bars as small square grids, each square a point; the terminal as braille dots. On both, each tenth fills its left column from the bottom up, then its right, so a tenth half full or more stands full height, and the lit part fades in from the left, brightest at its front. The dim words can be pressed (a desktop button draws its label plain, so the colored figures sit beside them), and the repo and branch are links: the root's name and the `↳` folder open in the file explorer, `files`, `ctx`, `5h` and `7d` the panes of `changes-drill`, `context-drill` and `usage-drill` (each needs its mod; without it a toast says to install it), and the last slot's word cycles output and rate, cost, the session's turns and time, the turns left before auto-compact, and how long the prompt cache stays warm (`cache 42m`, yellow in its last five minutes, `cold` once it lapsed or after a model switch, compaction or /clear, `--` before the first reply; a reading only, nothing is sent to keep it warm; the `cacheTtl` option sets the TTL, else an hour on a subscription and five minutes otherwise). The generation rate (`@84/s`: output tokens per second of the last model request, `@~84/s` estimated while one streams, `waiting 3s` before its first token). A toast says when CI fails or passes, a conflict appears, a review lands or the PR merges. The PR comes from `gh pr view`, so it needs `gh` signed in; no PR, no segment. When a refresh fails (offline, expired sign-in) the last reading stays up, dim. Draws under the prompt by default (visible while Claude works); `placement: above` draws it as a band above the prompt instead. On the desktop app it leaves out the model and effort (its model picker shows them) and the PR (its PR bar shows it; the toasts stay), and a narrow band wraps between segments instead of inside them. |
| `context-drill` | this repo | A Context pane that drills into what fills the window. Read when it opens, after each turn while it is shown, and on Refresh: the local `summary` estimate and the session's own transcript, no request sent; nothing is read while it is closed. Top to bottom: the fill in motta-statusline's ctx colors (green under 30%, yellow to 50%, orange to 70%, red past it), the /context categories as a stacked square bar across the pane with a tick where auto-compact fires (or a list, or /context's grid) and a two-column legend with what each grew since the pane opened; then foldable sections in one aligned table (label, mini bar, figure): the fill per turn as a line against the auto-compact point with the average growth, turns left before auto-compact, cache health of the last request (read, written, fresh), the heaviest messages and tool results, tokens by tool with calls, the memory files, MCP tools by server (loaded tools only), agents and skills; then the startup cost against your average in the project (kept in the plugin store). A footer picks what a compaction keeps (everything, the current task, the decisions, or your own words) beside Compact now and Refresh. A toast says when the fill turns orange or red. Every part is a `userConfig` setting. The desktop draws the bars as square grids, a terminal as braille. `motta-statusline`'s `ctx` opens it, through `$.contextDrill.open()` (a mod opens only its own panes); `/context-drill` opens it too. |
| `changes-drill` | this repo | A Changes pane for what the desktop's diff view does not say. Files are grouped by the turn that last changed them, titled with that turn's prompt (or by folder, by who, or by staged state), and each says who changed it: Claude, a subagent, Claude's shell, or you outside Claude. The baseline is HEAD, the session's start, the last turn or the base branch (a `git stash create` snapshot that leaves the stash list alone; local refs only, nothing fetched). Each row lines up its status letter, path, pills, a bar of lines added and deleted, the counts and its age. A guard marks sensitive files (`.env`, keys), with a toast when one is untracked and not ignored, and, with a `scope` set, files outside it. Opt-in: a churn flag for files edited many times, a no-test hint, folding generated files, and a peek that shows a file's first diff lines when pressed. Only the last two turns are drawn open; older ones fold under one line with a Show. Under the list, a History section: Current (what happened, in sentences, or the changed files as a tree, with its picker), and a **Branches ▸** button that opens `branch-drill`'s pane for Me and All (without it installed, a toast says to install it). It reads local git when the pane opens, at a turn's end when a branch moved, and on its own Refresh, never with the pane closed. Read-only: nothing it draws stages, reverts or writes; no model calls, nothing added to the context, no network. Turns and edits come from the engine's events, or after a restart from the session's own transcript; files from local git, read on open, on Refresh and at the end of each turn while the pane is up (with it closed, once at the end of a turn that changed files, for the toasts). | `branch-drill` | this repo | A Branches pane on top of `changes-drill` (it needs it): Me (your branch against main, or where your work sits: files, branch, GitHub, main) and All (every branch as GitKraken-style lanes, text art in the terminal, or a subway map), each with its own picker; on the desktop, hovering a commit or a term shows a card, a branch lights up together, and clicking a commit opens its files. | `usage-drill` | this repo | A Usage pane: each rate limit (5h, 7d) as `motta-statusline`'s bar across the pane (its colors and pace tick), its percent and reset, and a verdict (on track, tight, ahead of pace, runs out at 21:05). Under its details (open by default, `d` closes them), 5h and 7d side by side: the readings this window against an even pace, burn rate, hourly budget, cost per turn, this session's share, past windows and when each clears; then the weekly limit's activity as GitHub draws contributions (days by three-hour slots) and a cross of the spend by model family (Opus, Sonnet, Haiku, Fable). | `assumption-check` | this repo | A side pane, beside `/filetree`, of the assumptions Claude makes, one dropdown per prompt. Four counts sit on top: to check, low confidence, corrected and confirmed; press one to show only its cards, again to show all. Each card holds the assumption, why Claude made it, its confidence, category, source and what breaks if it is wrong; the source opens in VS Code at its line. Within a prompt, low-confidence cards come first and the first of a batch opens on arrival; one arriving while the pane is not shown raises a toast. Four buttons per card. **Right** marks it confirmed, and a prompt's **all right** confirms all its open cards; undo puts one back. **Wrong** opens a field: type the right assumption, or leave it empty and Claude asks you; either way Claude first lists what it built on the wrong one. **Why?** asks Claude for its reasoning. **Delete** removes the card from the mod's memory, and a prompt with no cards left leaves the pane. Only wrong and why? reach Claude, each as a prompt; right and delete stay in the pane. On from the session start; `/assumption-check off`, or the `startOn` option set to false, turns it off: while off it adds no instruction, tool or note, so Claude works as without it. Main session only: a subagent's or teammate's call to the tool makes no card. |
| `prompt-enhancer` | this repo | `/enhance <text>` rewrites your draft before you send it: an **Enhance** pane opens with the text; it draws nothing above the prompt. pick one; only that one is written, in one model call. **Cleaned up**: a cheap model (`cleanModel`, `haiku` by default), with no conversation, fixes typos, fillers ("uh", "ah"), other voice-to-text artifacts and punctuation, and leaves every other word, the wording, the language and the structure as you wrote them. **Expanded**: the shortest prompt that keeps everything that matters, task first, with how to check the work and `[placeholders]` for facts it lacks, written with the conversation. Paths, @mentions, /commands and code come back verbatim, and the card names any the result changed. The pane shows the result under your draft (before and after) with the tokens spent. **Use it** puts the result in the box, **Send** sends it, **Copy** copies it; Use it, Send, cancel and discard close the pane, and closing it yourself cancels the job. Expanded's `model` option: `session` (default) forks this conversation, so it knows what "that" refers to, on the session's model and from the prompt cache (once the cache has lapsed, a long conversation is billed again in full); or `haiku`, `sonnet`, `opus` or a full id, sent the last messages as an excerpt, with an `effort`. Where an app does not let mods write the prompt box, the first **Use it** says so and the pane drops it. |
| `emotive-spinner` | this repo | The animated spinner line says what Claude is doing instead of a whimsical word: an emoji, plain words, and after the ellipsis the size or count. `📖 Reading hooks/register.tsx… · lines 1–200`, `📝 Writing notes.md… · 42 lines, 1.8 KB so far` (counted while the file streams in, the slowest part), `✏️ Editing README.md… · −4 +12 lines`, `💻 Install package dependencies…` (Claude's own description of the command; `🌿` for git and gh), `🔍 Searching "Spinner" in repo/plugins…`, `🌐 Fetching docs.anthropic.com…`, `🤖 Explore codebase… · 📖 Reading x.ts` (what the latest agent is doing), `🔌 slack: send message…`, `💭 Thinking…`, `💬 Writing the answer…`, `❓ Waiting for your answer…`, `⏳ Waiting for the model… · step 3`; calls at once are counted (`Reading 3 files`), and a todo or task in progress is added after them (`📋 Running tests`). Tools are read by the shape of their input (a path, a command, a URL, a pattern), so a tool added later still reads right, and one with nothing to go on shows its name in words (`🔧`). Everything comes from the engine's events (tool calls, the response as it streams, the spinner's mode); no model calls, no tokens. It rewrites the words only: the engine's star, time, tokens and colors stay, and a state's own message (compacting) is left alone; anything it cannot read leaves the engine's line. Terminal and desktop app. The desktop draws nothing after the ellipsis, so there the detail joins the words (`📝 Writing notes.md · 42 lines so far…`). When the desktop's row names a tool call itself, the longer wording wins: its own words stay when they say at least as much (`💻 Waiting five seconds for the check`), and a shorter one (`Creating`, `Running a command`) gives way to the mod's, which name the file or the command; while Claude waits, thinks or answers, the mod's words show, since the row still holds the last call's. **This replaces the desktop app's own text.** If that is unwanted, remove the length test in the `Spinner` hook of `hooks/register.tsx` (marked `NOTE`), and the app's words always win while a call runs. |

Third-party mods are vendored: an unmodified copy of the reviewed commit, with its license, lands in `plugins/<mod>/` in a commit of its own, and our changes come after it in commits of their own. To take an upstream update, review its diff from the commit named above, apply it over our changes, and move that commit in the table and in the mod's marketplace description.

## New machine

[setup/SETUP.md](setup/SETUP.md) makes a Windows machine's Claude match the others: log in, clone this repository, install the mods, merge the settings in [setup/](setup/), add the skills. Every step is a command with a check, so a Claude session pointed at that file can run it. It also lists what comes with your Claude account and what no machine can carry.

## Where mods draw

- **CLI:** everything.
- **Desktop app (Code tab):** the band above the prompt, panes and slash commands. It does not raise the hint line under the prompt, so `motta-statusline` draws in the band there on its own, without the model and effort the app's picker already shows. A session there runs each mod from the copy `claude plugin install` or `claude plugin update` made under `~/.claude/plugins/cache/`, even where `claude plugin list` names this checkout under `Read from`, and `/reload-plugins` does not swap a mod the session loaded at its start. An edit reaches it after a version bump, `claude plugin update <mod>@motta-claude-mods` and a new session.
- **claude.ai web and cloud sessions:** none; they do not load local plugins.

The band above the prompt is shared, and the mods' hooks on it run in an order none of them picks, so each tree says how it shares through its root Box's key: `band-beside:<mod>` draws at the right of the status line, `band-under:<mod>` under it, and an unkeyed tree takes the band. `savvy-progress` draws its running bar as a `band-under:` card under the status line, so `motta-statusline` (with `placement: above`, or on the desktop) keeps its lines above it; a `band-beside:` chip column, should a mod draw one, sits at the right end of the lines, lifted out of a card if it ended up in one; an unkeyed tree from another mod would take the whole band. Panes (`/filetree`, `/assumption-check`, `/agents-info`, the enhancer's) share one place too, as tabs: docked beside the transcript in the fullscreen layout from 110 columns, inline above the prompt otherwise.

## Hover cards

On the desktop app, every pane mod puts a card on what it draws: a pressable thing's card says what the press does, a figure's card drills into it. A card opens one row clear of its row, with a thin bar in its kind's color (blue a local action, amber a press that reaches Claude, red a destructive one, gray plain detail). The desktop app stops drawing a pane past about 1,100 elements or 300,000 characters, with no error, so on the desktop each pane draws at the richest level that fits 1,000 elements and 200,000 characters: it drops the plain detail cards first, then every card, then folds its longest lists (each fold says what it hid). The terminal draws no cards at all, and none of the folds.

## Developing

Add this checkout as a directory marketplace and edits go live in the CLI on `/reload-plugins`:

```
claude plugin marketplace add <path to this checkout>
```

Checks, per mod in this repo:

```
claude plugin validate plugins/<mod>
claude plugin test plugins/<mod>
```

Vendored mods go in as an unmodified upstream commit first, each patch as its own commit after it.
